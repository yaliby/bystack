התקנת ByStack Install ByStack

מתקינים פעם אחת את המרכז, ואז מוסיפים כל שרת בפקודה אחת. זהו. Install the control center once, then add each server with one command. That's it.

3 צעדים3 steps בלי הגדרות מסובכותNo complex config בלי לפתוח פורטים בשרתיםNo open ports on servers

כבר מריצים את ByStack? מה שאתם מחפשים הוא עדכון גרסה — המרכז ואז כל שרת, בסדר הזה. Already running ByStack? What you want is Upgrading — the Controller, then each server, in that order.

המרכז (Controller)The Controller ×1

מתקינים פעם אחת. הוא מריץ את הדשבורד ומרכז את הכל. Installed once. It runs the dashboard and ties everything together.

סוכן (Agent)An Agent ×N

עוזר זעיר שמוסיפים לכל שרת שרוצים לנהל. A tiny helper you add to each server you want to manage.

1

מתקינים את המרכזInstall the Controller

פעם אחת בלבד, על המכונה שתהיה מרכז הבקרה שלך. Once only, on the machine you want as your control center.

שורה אחת. זו הדרך המומלצת: One line. This is the recommended way: 

curl -fsSL https://raw.githubusercontent.com/yaliby/bystack/v0.5.0/scripts/install-controller.sh \
  | sudo sh
⬆️ רק ההתקנה הזו יודעת לעדכן את עצמה. המרכז יורד כקובץ אחד, אז גרסה חדשה היא החלפה אטומית של הקובץ — ואם היא לא עולה, הקודם חוזר למקומו לבד. בדשבורד זה כפתור אחד: Update system. Only this install can update itself. The Controller arrives as a single file, so a new release is an atomic replace — and if it does not come up, the previous one is put back on its own. In the dashboard it is one button: Update system.
⚠️ צריך systemd ו‑python3.12 על המכונה. הסקריפט בודק את שניהם לפני שהוא מוריד משהו, ואומר בדיוק מה חסר. Needs systemd and a python3.12 on the machine. The script checks for both before it downloads anything, and says exactly what is missing.
🔑 לפני שמכניסים משהו ל‑sudo sh — מותר להסתכל: … | less מציג את הסקריפט, ו‑… | sh -s -- --keys מדפיס את מפתחות החתימה שהוא מוכן לקבל מהם גרסה, ותו לא. Before piping anything into sudo sh, it is fair to look: … | less shows you the script, and … | sh -s -- --keys prints the signing keys it will accept a release from, and nothing else.

או, אם המכונה כבר מריצה Docker ואתם מעדיפים קונטיינר: Or, if the machine already runs Docker and you would rather have a container: 

git clone https://github.com/yaliby/bystack.git
cd bystack
echo "DOCKER_GID=$(stat -c '%g' /var/run/docker.sock)" > .env
docker compose up -d --build
⚠️ להריץ מתוך התיקייה ש‑git clone יצר — בגלל זה השורה השנייה היא cd bystack. הבנייה הראשונה לוקחת כמה דקות; אחריה זה שניות. קונטיינר מעדכנים במשיכת image חדש, אז בהתקנה הזו אין כפתור עדכון. Run these from inside the directory git clone just made — that is what the second line is for. The first build takes a few minutes; after that it is seconds. An image is upgraded by pulling a new one, so this install has no update button.
✅ זהו — הדשבורד כבר רץ. Done — the dashboard is now running.
2

פותחים את הדשבורדOpen the dashboard

אם התקנתם על המכונה שמולכם: If you installed on the machine in front of you: 

http://127.0.0.1:8000
— אוor —

אם התקנתם על שרת מרוחק שאתם מגיעים אליו ב‑SSH: If you installed on a server you reach over SSH:

הדשבורד מאזין ב־loopback בכוונה — שום דבר לא מבקש סיסמה מהדפדפן, אז המרכז לא חושף את עצמו לרשת בלי שביקשתם. מריצים אצלכם במחשב, לא על השרת: The dashboard binds to loopback on purpose — nothing asks a browser for a password, so the Controller does not put itself on your network unasked. Run this on your own machine, not on the server: 

ssh -N -o ExitOnForwardFailure=yes -L 8080:127.0.0.1:8000 you@your-server

משאירים את זה רץ, ופותחים http://127.0.0.1:8080. Leave it running and open http://127.0.0.1:8080.

💡 שני המספרים הם שתי מכונות שונות. 8080 הוא פורט אצלכם ואפשר לבחור כל פורט פנוי; 127.0.0.1:8000 זה מה שהמרכז מאזין לו שם. אם תקבלו Address already in use — זו התנגשות אצלכם, לא בשרת: תבחרו מספר שמאלי אחר. ו‑you@your-server זה שם מארח, לא כתובת URL — yali@192.168.1.224, בלי http://. The two numbers are two different machines. 8080 is a port on your machine — pick any free one; 127.0.0.1:8000 is what the Controller listens on over there. An Address already in use is a collision on your side, not the server's: pick a different left-hand number. And you@your-server is a hostname, not a URL — yali@192.168.1.224, no http://.

לחלופין, אם אתם סומכים על כל מי שמגיע לשרת הזה — echo "BYSTACK_BIND=0.0.0.0" >> .env ואז docker compose up -d, ואז http://<server-ip>:8000. רק ברשת פרטית. Or, if you trust every machine that can reach that server — echo "BYSTACK_BIND=0.0.0.0" >> .env then docker compose up -d, and open http://<server-ip>:8000. Private networks only.

כבר תראו שם את הקונטיינרים של אותה מכונה — המרכז מנהל את עצמו אוטומטית, אז אף פעם לא מוסיפים אותו כשרת. Either way you'll already see that machine's containers on the map — the Controller manages itself, so you never add it as a server.

3

מוסיפים את השרתיםAdd your servers

אם יש לכם רק מכונה אחת — דלגו על הצעד הזה. Skip this step if you only have one machine.

פעם אחת: פותחים את המאזין לשרתים Once: turn on the fleet listener

הסוכנים מתחברים אל המרכז בפורט 8443, והמאזין הזה כבוי עד שמבקשים. בקובץ packaging/bystack.container.yaml משנים שתי שורות תחת agents: — ומוסיפים ל‑server_names את הכתובת שהשרתים האחרים ישתמשו בה כדי להגיע לכאן: Agents dial in to the Controller on port 8443, and that listener is off until asked. In packaging/bystack.container.yaml, change two lines under agents: — adding to server_names the address your other servers will use to reach this one: 

agents:
  enabled: true
  server_names: ["localhost", "127.0.0.1", "::1", "10.0.0.5"]
docker compose up -d

ואז לוחצים Add host בדשבורד. יש שתי דרכים, זו לצד זו: Then click Add host in the dashboard. There are two ways, side by side:

1
Install it from here — מדביקים כתובות, נותנים משתמש root וסיסמה (או מפתח), ולוחצים. המרכז נכנס ב‑SSH, מתקין את הסוכן, מחכה שהמכונה תתחבר בחזרה, וממשיך לבאה. שרת אחד בכל פעם, ועוצר אם אחד נכשל.Install it from here — paste the addresses, give a root login (password or key), press the button. The Controller logs in over SSH, installs the agent, waits for the machine to dial back, and moves on. One at a time, and it stops if one fails.
2
Copy a command — לשרת שהמרכז לא יכול להגיע אליו: מאחורי NAT, לפטופ, רשת בלי SSH נכנס. מעתיקים שורה ומריצים אותה על אותו שרת.Copy a command — for a server the Controller cannot reach: behind NAT, a laptop, a network with no inbound SSH. Copy one line and run it there.
🔒 מה שתקלידו משמש לפתיחת חיבור אחד ולא נשמר בשום מקום — אין רשימת שרתים, אין מפתח שמור, ואין למרכז דרך לחזור למכונה הזאת אחר כך. זו לא הבטחה שמישהו צריך לזכור: פשוט אין קוד שכותב את זה. וגם: השרת עצמו לא צריך אינטרנט — הסוכן עובר באותו חיבור. Whatever you type opens one connection and is never kept — no host list, no stored key, and no way for the Controller to reach that machine again afterwards. Not a promise somebody has to remember: there is no code that writes it down. And the server itself needs no internet — the agent travels over the same connection.
⚠️ אם פרסמתם את הדשבורד לרשת (0.0.0.0) — אין לו מסך התחברות משלו, אז הטופס הזה שולח סיסמת root ברשת בלי הצפנה מעליה. עדיף להגיע דרך ssh -L. הדיאלוג אומר לכם את זה כשזה המצב. If you published the dashboard to your network (0.0.0.0) it has no login of its own, so this form sends a root password across it in the clear. Reach it over ssh -L instead. The dialog tells you when that is the case.

הפקודה של הדרך השנייה נראית ככה — אל תעתיקו את זו, היא דוגמה. זו שבדשבורד נושאת את הכתובת שלכם, את הטוקן שלכם ואת הגרסה שהמרכז שלכם באמת מריץ: The second way's command looks like this — don't copy this one, it's an example. The one in the dashboard carries your address, your token, and the version your Controller is actually running: 

curl -fsSL https://raw.githubusercontent.com/yaliby/bystack/v0.5.0/scripts/install-agent.sh \
  | sudo sh -s -- --controller wss://10.0.0.5:8443 --token bys_<your-token>

הטוקן מוצג פעם אחת — המרכז שומר ממנו רק טביעת אצבע, אז סגירת החלון מאבדת אותו. אם איבדתם, פשוט מוסיפים שרת שוב ומקבלים טוקן חדש. הוא חד־פעמי ופג מעצמו. The token is shown once — the Controller keeps only a digest of it, so closing the dialog loses it. If you lose it, add the host again and get a new one. It is single use and expires on its own.

🟢 תוך שנייה-שתיים השרת החדש מופיע על המפה. אם הוא מסומן כ־pending, פשוט לוחצים Approve — זו הדרך של הדשבורד לשאול "זה באמת השרת שלך?". Within a second or two the new server appears on the map. If it shows as pending, just click Approve — that's the dashboard asking "is this really your server?".

חוזרים על צעד 3 לכל שרת. זהו. Repeat Step 3 for every server. That's it.

עדכון גרסהUpgrading

שני שלבים, בסדר הזה: קודם המרכז, ואז כל שרת. הסוכן שואל את המרכז מה מותר לו ולא להפך — אז מרכז חדש עם סוכנים ישנים הוא צי עובד שפשוט יש בו פחות יכולות בשרתים שעוד לא הגעתם אליהם. הכיוון ההפוך, סוכנים חדשים מול מרכז ישן, לא נבדק ואינו הדרך. Two steps, in this order: the Controller, then each server. An agent asks the Controller what it can do, not the other way round — so a new Controller with old agents is a working fleet with fewer features on the hosts you haven't got to yet. The reverse, new agents against an old Controller, is not tested and is not the path.

⬆️ אם התקנתם בשורה אחת, שני השלבים הם כפתור אחד. בדשבורד, בפאנל Hosts: Update system. המכונה מושכת את הגרסה החתומה הבאה, בודקת אותה מול מפתח שלא נמצא עליה, מריצה אותה פעם אחת לפני שהיא עוצרת משהו, מחליפה — ואם המרכז החדש לא עונה תוך שלוש דקות, הקודם חוזר לבד. אחר כך הצי מתגלגל קדימה, שרת אחד בכל פעם. מטרמינל: sudo /opt/bystack/bin/bystack-manager request. If you used the one-line install, both steps are one button. In the dashboard, on the Hosts panel: Update system. The machine pulls the next signed release, checks it against a key that is not on it, runs it once before stopping anything, swaps it — and if the new Controller does not answer within three minutes, the previous one is put back on its own. Then the fleet rolls forward, one host at a time. From a terminal: sudo /opt/bystack/bin/bystack-manager request.

1. המרכז, בהתקנת Docker — מתוך אותה תיקייה שבה התקנתם: 1. The Controller, on a Docker install — from the directory you installed it in: 

cd bystack
git pull
docker compose up -d --build
⚠️ --build אינו קישוט. compose.yaml מציין גם image מפורסם וגם דרך לבנות אחד, אז בלי הדגל הזה docker compose up -d מוצא את ה‑:latest שכבר על המכונה, משתמש בו, ומדווח Started — קיבלתם הצלחה על תוכנה ישנה. (--pull always היא התשובה הנכונה השנייה, אם אתם מעדיפים לקחת את ה‑image המפורסם במקום לבנות.) --build is not dressing. compose.yaml names both a published image and a way to build one, so without it docker compose up -d finds the :latest already on the machine, uses it, and reports Started — success on the old software. (--pull always is the other correct answer, if you would rather take the published image than build.)
📌 אם הפעלתם את המאזין בצעד 3, ערכתם את packaging/bystack.container.yaml — קובץ שכן נמצא ב‑git, אז git pull עלול לעצור עם Your local changes would be overwritten. שומרים על העריכה שלכם: git stash, אחר כך git pull, אחר כך git stash pop, ורק אז docker compose up -d --build. If you turned the listener on in Step 3, you edited packaging/bystack.container.yaml — a tracked file, so git pull may stop with Your local changes would be overwritten. Keep your edit: git stash, then git pull, then git stash pop, and only then docker compose up -d --build.

הנתונים שלכם ב‑volume ולא נגעו בהם — ה‑CA, רשימת השרתים הרשומים, יומן הפעולות ורשימות המעקב שורדים. גם .env שורד, כי הוא לא ב‑git. לוודא שאתם באמת מריצים את מה שחשבתם: Your data is a named volume and is not touched — the CA, the enrolment registry, the audit log and your watch lists all survive. .env survives too, since git does not track it. Confirm you are running what you think you are: 

curl -s localhost:8000/api/v1/healthz

ה‑version שבתשובה הוא של המרכז, והוא אותה מחרוזת שאליה פקודת Add host מצביעה. The version in that answer is the Controller's, and it is the same string the Add host command points at.

2. כל שרת — לא צריך להרכיב את זה לבד 2. Each server — you don't have to compose this yourself

אחרי שהמרכז עודכן, פאנל Hosts בדשבורד מציין אילו שרתים נשארו מאחור ומראה את השורה המדויקת להריץ (וגם bystack-ctl hosts עושה את זה). זו אותה פקודה שהתקינה את הסוכן, עם התג החדש ב‑URL ובלי --token: Once the Controller is upgraded, the Hosts panel names the servers that are behind and shows the exact line to run (so does bystack-ctl hosts). It is the command that installed the agent, with the new tag in the URL and no --token: 

curl -fsSL https://raw.githubusercontent.com/yaliby/bystack/v0.5.0/scripts/install-agent.sh \
  | sudo sh -s -- --controller wss://10.0.0.5:8443
🔑 היעדר הטוקן הוא מה שהופך את זה לעדכון ולא לשרת שני. התעודה ב‑/var/lib/bystack-agent היא הזהות של המכונה הזו מול המרכז והיא נשארת במקום; טוקן שיושב ליד תעודה קיימת גורם לסוכן להירשם שוב, והשרת חוזר כזר שממתין לאישור בזמן שזה שיש לכם נאלם. Leaving the token out is what makes this an upgrade instead of a second host. The certificate under /var/lib/bystack-agent is this machine's identity to the Controller and stays where it is; a token beside a stored certificate makes the agent enrol again and appear as a stranger awaiting approval, while the host you actually have goes quiet.

לא צריך לעצור כלום מראש. הבינארי החדש מחליף את הקובץ הישן במקום להיכתב דרכו, אז הסוכן הרץ מסיים על זה שאיתו התחיל והשינוי תופס בהפעלה מחדש שהסקריפט עושה בסוף — השרת נעלם מהמפה לשנייה־שתיים וחוזר. דגלים שהעברתם בפעם הראשונה, כמו --read-only או --socket, נשמרים בלי לחזור עליהם, והסקריפט מדפיס אילו נשמרו. העברה מחדש של דגל עדיין גוברת — ככה משנים דעה. You do not need to stop anything first. The new binary replaces the old file rather than being written through it, so the running agent finishes on the one it started with and the change takes effect at the restart the script does at the end — the host drops off the map for a second or two and comes back. Flags you passed the first time, like --read-only or --socket, are kept without being repeated, and the script prints which ones it carried over. Passing one again still wins, which is how you change your mind.

בשרת בלי גישה ל‑GitHub: מורידים או בונים את הבינארי פעם אחת, מעתיקים אותו, ומריצים את הסקריפט עם --binary ובלי טוקן. אחר כך Hosts מציג את הגרסה של כל סוכן, אז שרת שפספסתם נראה לעין ולא רק שקט. On a server with no route to GitHub: download or build the binary once, copy it over, and run the script with --binary and no token. Afterwards Hosts shows each agent's version, so a server you missed is visible rather than merely quiet.

הסרת שרת בהמשךRemoving a server later

מריצים על אותו שרת — אותו סקריפט שהתקין, עם דגל אחד ובלי כתובת ובלי טוקן:Run this on that server — the same script that installed it, with one flag and neither an address nor a token:

curl -fsSL https://raw.githubusercontent.com/yaliby/bystack/v0.5.0/scripts/install-agent.sh \
  | sudo sh -s -- --uninstall

התעודה ב‑/var/lib/bystack-agent נשארת בכוונה: היא מה שהמרכז מזהה בו את המכונה הזו, ומחיקתה הופכת "התקנתי מחדש את הסוכן" ל"שרת חדש הופיע והישן נאלם". למחוק אותה במפורש אם זו הכוונה. The certificate under /var/lib/bystack-agent is left behind on purpose: it is what the Controller knows this machine as, and removing it turns "I reinstalled the agent" into "a new host appeared and the old one went quiet". Delete it deliberately if that is what you mean.

כל ההתקנה. מרכז אחד, ואז פקודה אחת לכל שרת. That's the whole install. One Controller, then one command per server.
